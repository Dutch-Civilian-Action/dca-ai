# Dutch Civilian Action — Design System

**Dutch Civilian Action (DCA)** is a civilian humanitarian organisation supporting Ukraine through logistics, operational support, evacuations, fundraising, partnerships, transport coordination, and direct aid delivery. It is community-driven, operationally grounded, and human-centred.

The brand exists to make humanitarian work **visible, understandable, trustworthy, and traceable** — not to perform. Every design decision here flows from one idea: **Need → Action → Delivery → Impact**. This is not a slogan; it is the actual structure of every operation, report, and communication DCA produces.

## About DCA

DCA operates across eight connected domains:

| Domain | What it does |
| --- | --- |
| **Logistics** | Sourcing, transport coordination, route planning |
| **Operations** | Field coordination, evacuation support, direct delivery |
| **Fundraising** | Community campaigns, donor appeals, transparent reporting |
| **Finance** | Budget tracking, cost accountability, financial transparency |
| **Communication** | Public content, social media, updates, reporting |
| **Reporting** | Donor reports, operational reports, traceability |
| **Partnerships** | External orgs, institutions, local partners |
| **Community** | Volunteers, supporters, long-term trust building |

Community is not a marketing channel — it is an *output* of a well-functioning operational system. The 2026 strategy formalises this: real operational credibility, made visible and traceable, builds the community naturally.

**Mission:** DCA supports civilians and frontline communities in Ukraine through connected logistics, operational support, fundraising, and transparent communication.

**Vision:** A humanitarian system where support remains traceable from reality to impact, and where trust is built through visible operational reality, transparency, and human connection.

## Content fundamentals

### Voice

DCA voice is: **clear · grounded · human · structured · operational · direct · trustworthy · calm**

Understandable without being simplistic. Less is more.

### Brand principles

1. **Reality first** — Communicate real needs, real operations, real constraints, real deliveries, real outcomes. No abstraction, performance, or image-building.
2. **Human, not corporate** — Feel human, grounded, direct, accessible, emotionally real. Avoid corporate language, startup language, NGO clichés, inflated emotional framing, exaggerated inspirational language...
3. **Structured transparency** — Whenever possible, connect Need → Action → Delivery → Impact. The audience should understand not only *what* happened, but *how it connects*.
4. **Operational credibility** — Specificity builds trust. Use real numbers, real timelines, real locations, real operational details, concrete examples... Avoid vague claims.
5. **Calm seriousness** — Urgency may exist, but panic, sensationalism, and emotional manipulation must be avoided.

### Writing style

**Use:**

- Short paragraphs
- Active voice
- Concrete, operational language
- Real numbers, timelines, locations
- Direct phrasing
- Visible human context

**Avoid:**

- Buzzwords, corporate language, startup language
- NGO clichés ("change lives", "making a difference", "empowering communities")
- Excessive abstraction or vague "impact" claims
- Exaggerated urgency
- Motivational clichés
- Overly polished storytelling

### Story structure

Structure every communication as: **Need → Action → Delivery → Impact → Continuation**

The audience should understand not just what happened, but how it connects. Example:

> A hospital in Kharkiv needed backup generators.\
> Generators were sourced in the Netherlands and transported via partner logistics.\
> Delivery was completed on 14 March.\
> The generators became operational within 24 hours.\
> Continued fuel supply is still needed to keep them running.

### Copy examples

| ✅ Preferred | ❌ Avoid |
| --- | --- |
| "Fuel funding supported evacuation transport for the past 7 days." | "Your donation changes lives." |
| "3 generators delivered to Kharkiv, 14 March." | "We are making a real difference." |
| "We are currently waiting on customs clearance in Poland." | "Thanks to you, hope is restored." |
| "Transport for 12 families, Zaporizhzhia → Kyiv, 22 Feb." | "Every contribution matters." |

### Casing

- **Sentence case** for headings, body, captions — always.
- **UPPERCASE** reserved for short eyebrow labels and status badges only (`LOGISTICS`, `URGENT`, `DELIVERED`).
- No SHOUTY paragraphs, no Title Casing of Sentences.
- **Emoji:** not part of the brand. Never use as icons or decoration.

### Tone by context

| Context | Tone |
| --- | --- |
| Fundraising appeals | Urgent but grounded. Human and emotionally real — no manipulation. |
| Operational updates | Clear, factual, structured, concise. |
| Donor reporting | Transparent, traceable, concrete. |
| Social media | Human, immediate, visual, accessible. Lead with a real operational fact before inviting action. |
| Website content | Clear, structured, trustworthy, easy to navigate. |
| Crisis communication | Short, calm, factual, direct. |
| Community & volunteer | Warm, appreciative, human. |

### The Presence-to-Participation flow (social media)

Rather than converting followers with emotional appeals, DCA moves from **Presence** (authentic operational reality) to **Connection** (trust-based participation). Every post leads with a moment of Presence — a real, specific operational fact — before any call to action. This specificity builds long-term trust rather than short-term emotional highs.

### Transparency and honesty

- Do not communicate claims that cannot be reasonably validated.
- If information is uncertain, state the uncertainty clearly. Never present assumptions as facts.
- When discussing funding: remain concrete, explain operational relevance, avoid inflated impact framing.
- Do not publish unsafe location details, identifiable vulnerable individuals without consent, or sensitive operational information. Operational safety always comes first.

### Human dignity and the Alt Text Rule

All communications must follow the **Alt Text Rule**: images are described purely in terms of their physical reality ("A woman receiving a package", "A warehouse with palletised cargo") — never in terms that dictate feelings, assign victim status, or reduce people to their suffering. No exploitative imagery; prioritise consent and safety.

## Visual foundations

The visual language is **real, operational, documentary, grounded, minimally processed..**. Authenticity over polish.

### Colour

**Primary palette (verbatim from guidelines):**

| Token | Hex | Use |
| --- | --- | --- |
| `--dca-blue` | `#1863B5` | Operational trust, logistics, links, structure, informational hierarchy |
| `--dca-yellow` | `#FBD149` | Visibility, highlights, campaign emphasis |
| `--dca-orange` | `#FF813D` | Warmth, urgency, calls to action, humanitarian energy |
| `--dca-black` | `#010000` | Typography, hierarchy, strong contrast, minimal layouts |

**Supporting tones (use sparingly; never overpower primaries):**

| Token | Hex | Use |
| --- | --- | --- |
| `--soft-peach` | `#FFE3D4` | Calm backgrounds, breathing room, social media templates |
| `--light-orange` | `#FF9C66` | Secondary highlights, softer CTA backgrounds |
| `--light-grey-blue` | `#E0EFEE` | Report backgrounds, info cards, neutral section separators |

**Operational status colours** (the trace system):

| Token | Use |
| --- | --- |
| `--status-need` (orange) | Identified need / urgent |
| `--status-planned` (grey) | Planned / queued |
| `--status-progress` (blue) | In progress / in transit |
| `--status-delivered` (green) | Delivered / completed |
| `--status-impact` (yellow) | Impact / ongoing support |

**Accessibility:** Text and background combinations must remain readable. Readability always takes priority over visual complexity. Avoid low-contrast combinations and visually noisy layouts.

### Typography

**Roboto Condensed** is the primary system. **Roboto Mono** carries operational data.

| Weight | Use |
| --- | --- |
| Roboto Condensed Black (900) | Headings, titles, campaign emphasis, major operational statements |
| Roboto Condensed ExtraBold (800) | Strong sub-headings, feature text |
| Roboto Condensed Bold (700) | Emphasis, section headings, CTA elements |
| Roboto Condensed Regular (400) | Body text, descriptions, long-form content |
| Roboto Regular/Bold | Readable alternate for UI where condensed is too narrow |
| Roboto Mono Regular/Bold | Figures, operational codes, costs, timestamps |

Typography principles: strong hierarchy, large clean headings, readable body text, consistent spacing, minimal mixing. No decorative fonts, no type effects or shadows.

Alternative digital fonts (when platform limitations apply): **Canva Sans**, **Inter**.

### Spacing and layout

- **4px base grid** — all spacing tokens are multiples.
- Generous spacing; operational content needs room to breathe.
- Report/long-form reading width: `--container-md` (820px).
- Page container: `--container-xl` (1280px).
- Page gutters clamp from 20px to 64px (`--gutter-page`).
- Fixed sticky header on the website; sticky detail panel in the operations console.

### Backgrounds and imagery

- Mostly **clean white** (`--neutral-000`) and subtle neutral/info surfaces.
- Occasional **full-bleed dark** (`--dca-black`) bands for transparency or impact statements.
- **Imagery is documentary** — real operational photos (loading, transport, delivery, coordination, volunteers working). Warm, unprocessed, not staged. No stock imagery, no heavy overlays, no dramatic manipulation. Placeholders in the kits stand in for real photos.
- No gradient hero backgrounds, no purple/blue decorative gradients.

### Cards, borders, and radii

- Geometric and restrained, echoing the diamond mark in the logo.
- **Radii:** very small — 2px (`--radius-xs`) to 12px (`--radius-lg`) for cards. `--radius-pill` (999px) for badges and tags only.
- **Cards:** hairline 1px neutral border, white surface, subtle `--shadow-md` only when raised/interactive. Tint cards with `--surface-info` (grey-blue) or `--surface-calm` (peach) for report sections.
- **Do not** use rounded-corner + coloured-left-border-only cards — this is a cliché the brand avoids.

### Elevation and effects

- Subtle, neutral-toned shadows (`--shadow-sm`, `--shadow-md`, `--shadow-lg`) only to lift interactive surfaces.
- No glows; no decorative gradients; no purple or blue hero washes.
- Transparency/blur used lightly (e.g. translucent sticky header at scroll) — not as decoration.
- **Focus ring:** 2px blue ring with offset (`--shadow-focus`).

### Motion

- **Calm. No bounce.** Standard ease: `cubic-bezier(0.2, 0, 0, 1)` (`--ease-standard`). Durations: 120ms fast, 200ms base, 320ms slow.
- Progress bars ease their fill. Navigation transitions are instant or very quiet.
- Always respect `prefers-reduced-motion`.
- No infinite decorative loops or bouncing animations.

### Hover and press states

- **Hover:** darker brand shade (e.g. `--dca-blue` → `--dca-blue-700`) or soft tint on ghost elements (`--dca-blue-050`). Links gain underline.
- **Press/active:** 1px downward nudge on interactive elements. No scale transforms or shrink effects.
- **Focus:** 2px offset blue ring (`--shadow-focus`).

## Iconography

- **No official DCA icon set exists.** The brand guidelines specify no icon font, sprite, or SVG library.
- **Substitution (flagged):** The UI kits and component cards use **[Lucide](https://lucide.dev)** — loaded from CDN (`unpkg.com/lucide`). Lucide is a clean, even-stroke (\~2px) line set that matches DCA's calm, operational, minimal tone. Swap for an official set if one is ever adopted.
- **No emoji** in brand communications. Never used as icons or decoration.
- **Unicode arrow (`→`)** is used in copy to represent the Need→Action→Delivery→Impact flow — not as general UI iconography.
- Keep icons functional and sparse. Labels do the work; icons support, never decorate.
- Icon colour follows content hierarchy: `--text-body` for neutral, brand colours for status and emphasis.

## Using the system

Link the one stylesheet and read components from the namespace:

```html
<link rel="stylesheet" href="path/to/styles.css">
<script src="path/to/_ds_bundle.js"></script>
<script>
  const { Button, Badge, Card, Eyebrow, Stat, Input, Progress, Trace } = window.DesignSystem_cf89c3;
</script>
```

All visual properties are CSS custom properties — override at `:root` or on a scoped selector to theme a section. Keep every claim in your designs concrete and traceable. When in doubt, ask: can this be verified? If not, rephrase.
